# `@chronoflow/frontend`

The ChronoFlow dApp: connect Freighter, lock funds in a Soroban escrow vault, watch the milestone
timeline unlock over time, and release or claw back funds straight from the UI.

```
src/
├── app/                Next.js 14 App Router (layout, dashboard page, global styles)
├── components/
│   ├── wallet/         WalletProvider — Freighter connect, reconnect, network check, signing
│   ├── ui/             Button, Card, Badge, Field, Callout, Stat
│   ├── Header · StatsGrid · CreateVaultForm · VaultList · VaultCard
│   └── MilestoneTimeline · VaultActions
├── hooks/              useNow (ticking clock), useVaults/useStats (polling), useTransaction
├── lib/                config, api, soroban, freighter, format, schedule, validation, types
└── generated/          chronoflow.ts — contract spec written by the deploy script
```

## Quickstart

```bash
pnpm install
cp .env.example .env          # NEXT_PUBLIC_API_URL (defaults to http://localhost:4000)
pnpm --filter @chronoflow/frontend run dev      # http://localhost:3000
```

You need [Freighter](https://www.freighter.app/) installed, switched to **Testnet**, and funded via
<https://friendbot.stellar.org>. Start the indexer API too (`pnpm run dev` from the repo root runs
both), otherwise the vault list reports that the API is unreachable — writes still work, since they
go straight to the contract.

## Features

- **Connect Wallet** — Freighter connect button with silent reconnect on load, a network badge, and an
  inline warning if the wallet is on the wrong network.
- **Initialize a vault** — recipient, token (XLM by default), amount, duration (minutes/hours/days)
  and milestone count, validated client-side against the same rules the contract enforces (address
  formats, positivity, `amount % milestones == 0`, `1 ≤ milestones ≤ 100`), with a live preview of the
  per-milestone amount and cadence.
- **Interactive timeline** — a segmented bar of every milestone (locked / unlocked / released /
  cancelled), locked-vs-unlocked fund totals, countdowns to the next unlock and completion progress.
  State is recomputed every second from `start_time`/`duration`/`milestones`, so it stays live between
  indexer polls.
- **Direct contract actions** — `Release Milestone` (labelled `Claim Payout` when you are the
  recipient; permissionless on-chain) and `Clawback Escrow` (funder only, enabled once the grace
  period elapses, with a countdown until then). Failures are translated from contract error codes into
  plain-language guidance, and successes link to the explorer.

## How writes work

```
validate → build tx → server.prepareTransaction() → Freighter sign → sendTransaction → poll
```

`prepareTransaction` simulates the call, attaches the ledger footprint and records the required
Soroban authorization entries (the funder's signature for `create_vault`, for example), and Freighter
signs the envelope plus those entries. `src/lib/soroban.ts` maps the host's
`Error(Contract, #n)` codes back through the generated spec so users see e.g. _"The next milestone
has not unlocked yet — wait for its unlock time. (MilestoneLocked)"_.

Reads use two paths: the indexer API for lists/aggregates, and direct contract simulation
(`get_vault`, `vault_count`, `unlock_time`) so the UI can still show live state when the indexer is
down.

## Configuration

| Variable              | Default                 | Notes                                                                           |
| --------------------- | ----------------------- | ------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_API_URL` | `http://localhost:4000` | Indexer API base URL. **Inlined at build time** — changing it needs a new build |

Contract id, RPC url, network passphrase, native-asset contract id and the explorer bases all come
from `src/generated/chronoflow.ts`, regenerated by
`pnpm --filter @chronoflow/contracts run deploy:testnet`. Nothing else needs editing to retarget the
dApp.

## Tests

```bash
pnpm --filter @chronoflow/frontend run test        # vitest (38 tests)
pnpm --filter @chronoflow/frontend run lint        # next lint
pnpm --filter @chronoflow/frontend run typecheck   # tsc --noEmit
pnpm --filter @chronoflow/frontend run build       # production build
```

The suite covers the pure logic that is easy to get wrong: amount formatting and parsing (bigint-safe,
precision-preserving), the milestone schedule maths (mirroring the contract's integer division), form
validation, and contract-error translation. Wallet and RPC calls are not exercised — those need a
browser with the extension installed.

## Screenshots

The README images in `docs/images/` are captured from this app by
[`scripts/capture-screenshots.mjs`](scripts/capture-screenshots.mjs), which drives headless Chromium
over the real stack (indexer API + built dApp):

```bash
pnpm exec playwright install chromium           # once: ~115 MB browser download
pnpm run screenshots                            # http://localhost:3100
pnpm run screenshots -- https://your-dapp.vercel.app
```

```bash
# No root on this machine? Stage Chromium's shared libraries inside the package:
node scripts/fetch-browser-deps.mjs             # → .browser-deps/ (gitignored, no system changes)
```

Unlock states are derived from the clock, so a vault made a month out and one made a minute ago give
you the locked / unlocked / released states in one shot. The wallet stays disconnected: the Freighter
extension cannot be automated, so the shots show the connect prompt rather than a signed-in session.

## Deploying

Vercel: import the repo, keep the root directory at the repository root (the monorepo build is
preset in `vercel.json`), and set `NEXT_PUBLIC_API_URL` to the deployed API. Details and the
post-deploy checklist are in [`docs/deployment.md`](../../docs/deployment.md).
